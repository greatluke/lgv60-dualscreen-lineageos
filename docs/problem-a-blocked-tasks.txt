Problem A -- blocked-task evidence
=================================

Captured on an LG V60 (timelm) running LineageOS, with the Dual Screen attached at power-on and
the attach failure active (repeated "hub failed to enable device, error -108"), via:

    adb shell "su -c 'echo 1 > /proc/sys/kernel/sysrq; echo w > /proc/sysrq-trigger'"

Both workers were still blocked ~733 seconds into the boot, i.e. permanently.

Read it as a pair. k_sm_usb is stuck tearing xHCI down inside hub_quiesce(); dwc3_wq is stuck
waiting for exactly that work to finish, in the flush_delayed_work() at the top of
dwc3_ext_event_notify(). dwc3_wq is an ordered workqueue (max_active 1), so every later USB ID
event queues behind the blocked item and never runs.

Timestamps and the full causal chain: see dualscreen-attach-flow.md.
